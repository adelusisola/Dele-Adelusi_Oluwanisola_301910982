## Selected case study: Vant Personal (simulated)
A savings-first mobile bank for young Nigerian customers, based on the publicly described Vant app. It uses no real Vant schema, code or data.
- **Nature of the system:** customers save towards goals, and can also deposit, withdraw and transfer money.
- **Users of the database:** customers, support agents, compliance staff, finance staff and the app's backend.
- **Major data:** customers, NGN and USD accounts, transactions, savings goals, beneficiaries, an activity feed and KYC documents.
- **Key operations:** open an account, deposit, withdraw, transfer, fund a savings goal, and view an account statement.

## How to run
Portfolios 1 to 3 use a local PostgreSQL (tested on version 18). Portfolios 4 and 5 use Docker.

**Portfolios 1 to 3, one command.** It creates the database if needed, rebuilds everything in the right order, runs the checks and stops if one fails (about 4 minutes). It also regenerates the Portfolio 2 plan files.
```bash
./run_all.sh
```

**Portfolio 4** (needs the Portfolio 2 data, so run `./run_all.sh` first):
```bash
docker compose up -d mongo
portfolio-4-nosql/load.sh
docker exec vant-mongo mongosh --quiet vant_nosql /work/queries.js
portfolio-4-nosql/reconcile.sh
docker compose down
```

**Portfolio 5:**
```bash
docker compose --profile replication up -d pg-primary pg-replica
portfolio-5-distributed-cloud/replication_demo.sh        # stops the primary at the end
psql -d vant_personal -f portfolio-5-distributed-cloud/sharding.sql
docker compose --profile replication down -v
```
